CSR Generator

Fill in a few fields, hit go, and walk away with a CSR and the private key that matches it. Everything runs in this browser tab — nothing secret gets uploaded anywhere.

What’s a CSR, in human? A Certificate Signing Request is the “please issue me a cert for these names, with this public key” form you hand a certificate authority. It’s public-ish. The private key is the secret half — you keep that, never paste it into a CA form. After the CA sends back a certificate, your server needs cert + private key together.
Psst — your key never visits our server. Generation happens on your device with a library we ship alongside this page. Refresh the tab and the key is gone from memory, so download it while you’re here. We also re-parse the CSR after minting it and check that it matches your form and your key.

What are we signing up for?

Common Name + SANs cover most web certs. Optional org fields are there if your CA is picky.

SAN tip: Browsers and most CAs care about SANs, not just the CN. For a single hostname, add it under SANs too (we already fold the CN in). For sites that answer on both apex and www, list both — e.g. example.com and www.example.com.

Protect the key. A passphrase encrypts the private key file at rest (like a password on a vault). You’ll need it later in Cert Assembler or when installing on a server. Leave both blank only if you knowingly want an unencrypted key (lock the file down yourself).

    What do I do with this CSR?
    
          
    
            Generating the files is only half the adventure. Here’s the usual
            path from “I have a CSR” to “HTTPS actually works.”
          
    

          
      
            
    1. 
              Park the private key somewhere safe.
              Download it now, store it with the rest of the server secrets, and
              don’t email it to yourself “just for a second.” You will need this
              exact key when the certificate arrives. If you set a passphrase,
              store that password too — without it the key file won’t open.
            
      2. 
            
    2. 
              Submit only the CSR to your certificate authority.
              In their order / rekey / “provide CSR” form, paste everything from
              -----BEGIN CERTIFICATE REQUEST-----
              through
              -----END CERTIFICATE REQUEST-----.
              Leave the private key out of that form entirely.
            
      3. 
            
    3. 
              Finish domain (and maybe org) validation.
              The CA will ask you to prove you control the names on the cert
              (DNS record, HTTP file, email, etc.). OV/EV orders also check
              business details.
            
      4. 
            
    4. 
              Download the issued certificate.
              You’ll usually get a server cert plus intermediate/chain files
              (or a single bundle). Keep those with the key.
            
      5. 
            
    5. 
              Install cert + private key on the same server.
              Point nginx, Apache, Caddy, IIS, your load balancer, etc. at both.
              A cert without this private key won’t decrypt TLS; a key without
              the matching cert is just a lonely PEM file.
            
      6. 
          
    

          
    
            Don’t need a commercial CA?
            For a normal public website, free automated certs (Let’s Encrypt via
            Certbot, Caddy, etc.) often skip the “paste a CSR into a website”
            dance entirely — the tool creates the key on the server and renews
            for you. This page is for when a human-shaped CA form still wants a
            CSR.

    FAQ (the “wait, what?” section)
    
          
    Short answers, fewer foot-guns.
    

          
    
            What is a CSR?
            
    
              A Certificate Signing Request is a small public file that says
              “here’s my public key and the names I want on a certificate.” You
              send it to a CA; they send back a cert. The matching private key
              never goes in the CSR — and modern TLS mostly trusts the SAN list
              for which hostnames the cert covers.
            
    
          
    

          
    
            Do you ever see my private key?
            
    
              Nope. The key is created in your browser with a JavaScript library
              we host next to this page. It isn’t posted to a backend, logged, or
              emailed to a mysterious admin. If you’re extra spicy about it, open
              DevTools → Network while you generate and watch… nothing secret
              leave the tab.
            
    
          
    

          
    
            What does “Verified in this browser” mean?
            
    
              After generation we re-parse the CSR PEM, check that its signature
              is valid for the embedded public key, confirm that public key
              matches the private key you can download, and compare CN / SANs /
              subject fields to what you typed. That all happens locally — it’s
              a sanity check, not a third-party audit.
            
    
          
    

          
    
            Why do public CAs refuse to give me a private key?
            
    
              Because if they generated it, either they held something
              they shouldn’t, or they’d have to ship it to you over channels that
              are easy to mess up. Best practice: you create the key, you keep the
              key, you only send them the CSR (public request).
            
    
            
    
              This tool exists for the classic oops: “I got a certificate back and
              somehow never had the key.”
            
    
          
    

          
    
            What do I do with these files?
            
    
              Short version: stash the .key,
              paste only the .csr into your CA,
              then install the issued cert with that same key. Longer version
              (and vendor doc links): see
              What do I do with this CSR?
            
    
          
    

          
    
            Should I set a passphrase on the private key?
            
    
              Yes, when you can. It encrypts the key file so a stolen
              .key isn’t immediately usable.
              You’ll type that passphrase when assembling a PFX or when your
              server asks for the key password. The CSR itself is never
              passphrase-protected — only the private key file is.
            
    
          
    

          
    
            RSA or ECDSA — which should I pick?
            
    
              ECDSA P-256 is a great default for modern HTTPS:
              smaller keys, snappy handshakes. RSA 2048 is the
              “works everywhere including dusty appliances” choice. Reach for
              3072/4096 or P-384 if a policy doc is bullying you.
            
    
          
    

          
    
            I lost the private key after the cert was issued.
            
    
              Sorry — that’s a re-key story. Generate a new key + CSR, request a
              reissue/replacement from the CA, and retire the orphaned cert. We
              can’t fish the old key out of the void.
            
    
          
    

          
    
            Can I just use Let’s Encrypt instead?
            
    
              Often, yes! If you only need HTTPS on a public site you control,
              tools like Certbot or Caddy mint keys and certs right on the
              server and renew them for you. This CSR flow is for commercial CAs,
              internal CAs, email/client certs, or anywhere a human-shaped form
              still demands a CSR paste box.
            
    
          
    

          
    
            Is the OpenSSL snippet identical to the browser output?
            
    
              Same subject, SANs, and key type/size intent. Exact PEM bytes will
              differ (different random key). Requires OpenSSL 1.1.1+ for
              -addext. Older OpenSSL wants a
              config file instead — say the word and we can add that variant
              later.
