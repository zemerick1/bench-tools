    FAQ

    What order should the chain be in?

    This tool always writes the server (end-entity) certificate first, then appends the CA bundle in the order you pasted it. Many products want:

    1. End-entity / server certificate
    2. Sub / intermediate CA(s)
    3. Root CA (when the product requires it in-file)

    Example for ClearPass: ensure the certificate chain is arranged in that exact order — server first, intermediates next, root last. Web servers (Apache/Nginx) often want leaf + intermediates only; the OS trust store supplies the root.

    Do you upload my private key?

    No. Parsing and packaging run in your browser. Refresh the tab and it leaves memory.

    PFX vs P12?

    Same PKCS#12 container; only the file extension differs. Emit either (or both) depending on what the target UI accepts.

    What is the chain / bundle?

    Intermediate CA certs that link your leaf up toward a trusted root. Paste what the CA labeled “bundle,” “chain,” or “intermediate,” in the order the target product expects.

    Key doesn’t match certificate?

    The private key isn’t the one that matches this leaf (wrong CSR key, or cert for a different order). We won’t build a PKCS#12 from a mismatched pair.

    Local packaging only — not a CA, not a key vault. Part of the toolbox.
