Hardware Platform Support

One card per platform, with correlated firmware tracks: AOS-10 and Instant (IAP 8.x) — first / last support per track, and whether a track is still current or parked.

How data is joined: AOS-10 mins come from the New Central supported-devices matrix. Instant (IAP) mins/lasts come from Classic Central’s Supported Instant APs table (same model matched across sources). 700 Series Instant floor of 8.13.3.x is added on top of that table (not yet listed there). Expand a card for every track’s first/last.
About datasheets (and our pure intentions). In a perfect world I’d deep-link every model to its shiny official datasheet PDF so you could one-click from “is this parked?” to “how many radios does it even have?” Alas, HPE would rather we not send a fleet of helpful little robots to vacuum their entire documentation empire into a duffel bag. Scraping is discouraged; we heard them; we are behaving (mostly). So this page sticks to a hand-refreshed support snapshot plus release-note links—no clandestine datasheet heist, no “accidentally” mirrored PDF CDN, no trench-coat energy. If you need the glossy one-pager, the product site still has it. We just won’t pretend we nicked it for you.

FAQ

What are the firmware tracks?

AOS-10 — New Central / AOS-10 support matrix (AP, gateway, bridge, AOS-CX / AOS-S). Instant (IAP 8.x) — Instant OS support from the Classic Central Instant AP table (plus 700 Series at 8.13.3.x). One model can carry both tracks; filter by track to see only platforms that support that code.

What does “parked” mean here?

The official matrix lists a Last Supported Release. We label that parked: the platform is still documented, but capped on that train (for example 10.4.x.x). On AOS-10 rows, the release-notes button aims at the newest published notes under that train from the AOS-10 all-releases index.

How do you pick “latest AOS-10” for current platforms?

The RN Home page doesn’t always shout a single version number—it sends you to All Releases. We walk that list, take the highest version (semver-ish), and deep-link there. When you refresh the snapshot, that target moves with HPE’s catalog.

Where does the data come from?

Static snapshot of HPE’s Supported Devices page plus the AOS-10 All Releases link map. Refresh with python3 update_data.py when the public docs change (see README).

Why no datasheet links?

Because we asked the universe for “one polite table of support plus PDFs for every SKU,” and the universe (wearing an HPE lanyard) said scraping is a no-no. We’re not mad. We’re just… link-poor. Use the official product pages for datasheets; use this tool for “when did it ship on AOS-10 and is it parked?”

AOS-CX / AOS-S links?

Those platforms use different firmware trains. Rows still show minimum / recommended text from Central’s matrix; AOS-10 release notes buttons apply to AP, gateway, and bridge rows.
